Our recommendation: Option 4 — Cartoon Flat Detailed

Flat cartoon detail is the sweet spot for what you asked for: lots of detail, no realistic shading. Flat lines, stripes, shields, belts, helmet bands, and the white horse nose stripe are baked into the sprite once, so they cost almost nothing per frame — the sprite stays the same size and the same count. Shading gradients, soft shadows and supersampling are what cost frames. Option 4 keeps all the detail in the guys, adds MORE detail to the horse (nose stripe, mane, saddle, blanket, bridle, hooves, tail), and turns shading down to zero. If option 4 looks too busy, option 3 (Medium + Horse) is the closest simpler step. Options 9 and 10 look the same here on purpose: supersampling is bake-time only, it is downsampled to the same cached size, so it cannot change the picture, only how long a new pose takes to bake.

Pick a number and tell us: if you pick one, we will build it as a test game file first (like medium-no-blood), check it holds 16 ms on your phone, and only then put it in the real game.

What is real here, and what is a proposal?

Real game code, embedded verbatim: the base sprites are drawn by the actual v1.8.26 code — config.js, utils.js, render.js (Art.unit, Art.horse, Art.horseHi, Art.shield, unitBack/unitArmor/unitHead, Art.softShadow) and art-real.js (Art.person, Art.horseReal for options 9–10), loaded in order in this page. That is why options 1, 9 and 10 are real game sprites, not invented art.

Proposals, drawn on top in this gallery only: the flat overlays in options 2–8 (team shield, belt, helmet band, weapon tips, horse nose stripe, mane, saddle, blanket trim, bridle, hooves, tunic edge, shield cross, boots, helmet ridge, quiver, light rim, strong outline, 2-tone shade). They are NOT in the game yet. If you pick one, it will be built properly as a test file first.

Screenshots: this builder could NOT capture PNG screenshots on this VM — headless Chromium is blocked here by a Hatch WebGL domain policy (the same block as the earlier browser tests), and no node-canvas is installed. No PNGs were faked. Use the “Download this option as PNG” button under each option on your phone, or screenshot the page — those PNGs are rendered live by the same code above, not pictures of pictures.

Cost lines: sprite budget (Low 40 MB, High 80 MB, Ultra 160 MB), bake budget (Low 1.2 ms, High 1.6 ms) and frames/angles (flat 8/3, High 12/4) and supersample (High+v15 at sc≤2 = 2×, otherwise 1×) are taken from render.js. Cache “1.0× / ~2×” figures are estimates, marked as estimates, because exact cache use depends on the army mix in a battle.
